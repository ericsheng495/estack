# Cost-aware delegation

`delegate-work` defines proportional delegation: small work stays with the coordinator, substantial isolated work starts with one worker, and two substantial independent tasks can use two concurrent workers. More workers need a stated coverage/risk reason or explicit user preference. Each worker gets a scoped outcome, relevant paths, write ownership, a budget/stop condition, and a short evidence report. Nested delegation is off by default; one corrective follow-up is the default retry bound.

`skills/eric-mode/SKILL.md` loads this policy and gives it precedence over inherited mandatory panels, model defaults, and fresh-agent requirements. Fourteen standalone workflows also link it before spawning, including `how`, `architect`, `recall`, `swarm`, and `maintain-verification-skill`. `setup-estack` starts unconfigured roles on `inherit-parent` and panels with one entry. Explicit supported user configuration can select cheaper roles or request broader review.

Relevant feature documents and source pointers are passed to delegates instead of whole catalogs. Supported host tools determine actual worker types, model availability, and background execution. The coordinator owns integration and examines evidence rather than repeating searches.

## Verification and limits

The new skill passed schema validation. The coordinator reviewed the instructions and integration, and an independent review identified bypasses through standalone workflows; the routers and setup guidance were then updated. `docs/delegation.md` records the primary research and a proposed cost-comparison method.

This is an instruction policy. It does not enforce a token ceiling, configure billing, or select a cheaper model without supported configuration. No controlled model-behavior evaluation or cost benchmark was run. Subagents may increase total tokens. Usage and savings must be reported as unmeasured when the host does not expose them. Workflow verification requirements still apply.
